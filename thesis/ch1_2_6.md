# 第 1 章 绪论

## 1.1 研究背景

模型合并尝试复用同一基座上的微调专家，减少重新训练成本。本文关心的是：当效用只能通过实际生成与评分获得时，怎样在有限开发数据和昂贵调用下选择合并系数？这不仅是优化器问题，也取决于合并映射、评分规则、初始化、候选筛选、终选和数据独立性。

本项目采用 Qwen2.5-1.5B-Instruct 与十个原始 LoRA 专家，搜索二十个初始化候选或粒子。现有物化对 A/B factor 分别混合，真实模型增量带交叉项和系数尺度平方效应，不是线性 delta merge。有限 dev 的抽样误差、同题重复的执行波动及长期自适应选择过拟合必须分别处理。

## 1.2 研究内容与贡献边界

论文主线收敛为 **RACER 的多提案与竞速搜索，以及可追溯的评测证据**：

1. 明确 factor 合并的二次映射，识别尺度与方向对照中的混杂，不再使用“仿射包几何锁死”作为已证明定律。
2. 描述 RACER 在局部自适应、差分外推、尺度提案与分层评测之间分配调用的机制；将启发式、历史实现与下一阶段严格协议区分。
3. 建立显式 run 清单与标准库只读工具，恢复 PSO 的同 dev 选中粒子领域 H，纠正主表与结论。RACER/PSO/CMA 的十二任务宏平均分别为 **.4439167/.4327983/.4363333**；这是一组 legacy 描述性结果，不是显著性或严格等预算结论。
4. 将 legal 的共享题干、kcross 的实例族风险、SUMO 混配置、AMPHI 缺反事实和 SMM 简化代理实验纳入证据分层。

RACER 的历史平均较高是继续验证的理由，不是已经完成独立泛化证明。SUMO/AMPHI 作为探索性扩展，不再构成与 RACER 并列的已验证冠军叙事。

## 1.3 章节安排

第 2 章区分合并配方、搜索器与评测协议；第 3 章给出 factor 数学、数据及汇总诊断；第 4 章集中描述 RACER 与可重建历史主表；第 5 章报告 SUMO 配置组和 AMPHI 实际路由事件；第 6 章总结已成立证据与下一闸门。

# 第 2 章 相关工作

## 2.1 合并配方与参数化

Task Arithmetic、TIES、DARE 研究任务增量的组合或稀疏化；Model Soups 研究模型权重平均；Fisher/RegMean 使用数据或曲率相关信息。LoRA 的 factor 级平均与完整增量级平均一般不等价，不能把不同参数化上的结果直接归因于优化器，也不能笼统声称免搜索配方无法利用专家协同。

实际引用需按原文核验作者、发表场所、预算和效用。本文不通过未经核验的模型总量或“所有先行工作从未研究噪声”等绝对断言建立新颖性。

## 2.2 搜索式合并

LoRAHub 的 NGOpt、Sakana Evolutionary Model Merge 的进化搜索以及 Model Swarms 的 PSO 展示了不同搜索路线。它们的专家池、参数空间、目标（loss 或生成准确率）、预算单位和初始化不同。复用优化器名称不意味着复现其整套协议。

本文的 PSO 是现有本地 Model Swarms 路线档案；CMA 是本地 factor-space 基线，并非把 Sakana 的原始任务和预算搬到同一表。LoRAHub 文献中的二十 LoRA 也不应误写为本项目原始专家数。未补跑的 NGOpt 不能通过“引用即可排除”预先判定不必比较。

## 2.3 黑盒优化与评测设计

CMA-ES、差分进化/SHADE、多保真与 successive-halving 类方法提供候选生成和预算分配的通用部件。RACER 是面向该工程场景的组合，不将每个通用机制宣称为首次发明。高成本小预算并不理论上排除完整协方差、BO 或其他优化器；是否适合须靠匹配控制和实际成本比较。

评测协议与搜索器同等重要：固定评分、切片身份、逐题 raw 档案、稳定并列规则和独立终选，比单独列出优化器终点更能支持可重复比较。特别要防止开发与测试评分不一致、领域分项文件覆盖，以及把共享题干称为独立测试。

## 2.4 前沿素材的使用原则

MOBO-Merge、MERGEvolve、FusionBench、MergeBench、SMM-Bench，以及相关工作档案中的后续条目是待核验引用线索。多目标、全参数、层配方与系数搜索应分开讨论。几何上“凸包之外更好”若来自 delta 参数化，不能直接佐证本项目 factor 级三定律；SMMBenchPS 的局部引擎结果也不能与官方完整协议终点直接排冠军。

`doc/frontier_related_work.md` 保留已有周报内容并给出引用审计标签。本阶段不联网核验，因此不宣称“第一个”“生态位空置”或“零新增必比基线”已经完成全面检索。

# 第 6 章 总结与展望

## 6.1 已完成的实质结果

本文以 RACER 为主线，给出十维 factor 系数搜索的具体定义、多提案和竞速机制，并把历史实验从单纯高点展示转化为可审计证据。

历史主表经校正后，RACER 的十二任务宏平均为 .4439167，PSO .4327983，CMA .4363333；RACER 相对二者分别约高 1.11 和 .76 个百分点。PSO science 原 .156448 只反映末分项，恢复同 dev 选中粒子的 H 后为 .258326；legal 校正为 .588699。这改变了“修复巨大崩溃”的叙述。Soup 的十二行宏平均也由旧稿误写的 .410 更正为 .4003333。

已建立的清单同时保留双 seed RF、各基线、SUMO 配置组与 AMPHI 真实路由来源。它不扫描目录挑最高 test，不修改原 run，不能把聚合校正冒充严格重评分。

## 6.2 主要局限

- **评分**：历史解析及 dev/test 差异仍属 legacy。新 strict 是保守冻结 grammar，不等同于任何官方评分器复现；它避免 numeric substring 匹配，但无明确答案格式、单位/解释不符合 grammar 的输出可能判 invalid。必须报告 invalid 率及逐题 raw，不能把协议升级视为无偏提升。当前生成器仅返回 decoded 文本，未保留完整停止原因/token 数，故只能拒绝语法不完整或歧义，不能声称识别所有 max-token 截断；语法完整的截断仍可能漏检。
- **独立性**：legal 不支持独立泛化；kcross 有题干/实例族共享风险；其他任务独立性尚未认证。长期使用历史 test 调方法不能由当前清单冻结追溯消除。
- **选择与随机性**：RACER 两 seed、基线单 seed，PSO 历史种子身份不完整，终选与成本不匹配。重复相同 dev 不提供独立样本，未作统计显著性声明。
- **数学混杂**：factor 的交叉项和尺度平方效应尚未被配平实验分离；没有显式 final alpha 的旧模型不用于最终系数机制分析。
- **外部范围**：单一基座和原始专家池；SUMO 不是统一配置全谱；AMPHI 无等预算双分支反事实；SMM 只验证本地简化 PS 引擎，不是完整协议泛化。

## 6.3 下一闸门

首批只做 dev 尺度敏感性诊断：两个任务、两个固定方向、五个尺度，共二十配置以内，单本地空闲 GPU 累计不超过两小时；失败与重试计入，缺离线资源即停。pilot 的目标是检验尺度影响，不预设分数必涨，不读 test，不证明 PSO+scale 追平或 RACER 因果机制成立。

在扩大比较前，须完成真实互斥终选、PSO 域级返回/并列接线、搜索器硬预算及相同初始化空间；之后再批准 PSO+scale、CMA、matched Random 与 RACER 的多 seed 对照。第二专家池、新测试来源、delta merge、SUMO/AMPHI 反事实及官方 SMM 对手均是后续独立计划，不自动衔接扩跑。详细结论—证据—验收表见 `doc/experiment_plan.md`。
